# Personal Website

Content model and structure for a portfolio site presenting backend engineering projects as written case studies for an overseas technical audience.

## Language

**Project**:
One of the 9 backend repos being showcased on the site.
_Avoid_: Repo (when discussing site content, not the GitHub artifact itself)

**Case study**:
The full written essay (800–1500 words) for a Project, following the fixed 5-part structure (problem, stakes, design decisions, limitations, try-it-yourself).
_Avoid_: Write-up, post (when referring to the on-site version specifically)

**Coming soon stub**:
A Work-index tile for a Project whose Case study hasn't been written yet — shows the project title/summary and links directly to its GitHub repo instead of a case study page.

**Batch 1** / **Batch 2**:
The two sequencing groups for case study writing. Batch 1 (bank-ledger, todo-list, payment-gateway-webhook, rate-limiter) is written before launch. Batch 2 (the remaining projects) is written post-launch and added to the site as each is finished.

## Relationships

- The **Work** index page lists all 9 **Projects**, each as its own tile — one **Project** never shares a tile with another.
- A **Project** either has a **Case study** or renders as a **Coming soon stub** on the Work index.
- **Home** features 3 **Case studies** as a teaser section, linking into the full **Work** index: bank-ledger, payment-gateway-webhook, rate-limiter (todo-list is the Batch 1 project excluded from the Home teaser).

## Flagged ambiguities

- bank-ledger and todo-list were originally planned as a cross-linked "CAP Theorem in Practice" pair (shared framing, cross-links between the two case studies). Resolved: dropped entirely — each is written and presented as a fully independent **Project** with no reference to the other.
